Connect your host product to PatchSmith, define the capabilities apps can use, and render installed apps in React. You need an existing React frontend, a backend that handles standard `Request` and `Response` objects, and a [PatchSmith account](https://patchsmith.io/signup).

Get your project key from PatchSmith and make it available to your server as `PATCHSMITH_PROJECT_KEY`. Keep it out of client bundles. The examples use `@/` for your source directory; adjust imports to match your project.

<Step title="Define the shared contract">

Create `src/lib/patchsmith.ts` to define the contract between installed apps and your platform. It declares [components](/concepts/components), [views](/concepts/views), [slots](/concepts/slots), and scopes that identify an installation’s owner. Both your server and frontend import this file, so keep server credentials and logic elsewhere.

<Tip>
  Breaking contract changes, like removing a component or requiring a field, can
  break existing apps.
</Tip>

<Tabs>

<Tab title="Zod">

```ts src/lib/patchsmith.ts
import { defineContract, type Component } from "patchsmith";
import { primitives } from "patchsmith/zod";
import { z } from "zod";

// Define the components you want apps to use
const Button = {
  fields: z.object({
    variant: z.enum(["default", "secondary"]),
  }),
  callbacks: {
    onClick: {},
  },
  children: true,
} satisfies Component;

const Input = {
  fields: z.object({ value: z.string() }),
  callbacks: {
    onValueChange: {
      input: z.object({ value: z.string() }),
    },
  },
} satisfies Component;

export const contract = defineContract({
  // Values form the installation key, e.g. userId + teamId scopes installs per user per team.
  scopes: { user: z.object({ userId: z.string().min(1) }) },

  components: {
    // These give apps basic layout and styling components; we strongly recommend including them.
    ...primitives({
      // Customise these colors to match your app's design tokens.
      tokens: {
        borderColor: {
          default: "var(--border)",
          input: "var(--input)",
          destructive: "var(--destructive)",
        },
        textColor: {
          default: "var(--foreground)",
          muted: "var(--muted-foreground)",
          primary: "var(--primary)",
          destructive: "var(--destructive)",
        },
      },
    }),
    Button,
    Input,
  },

  // Views share page data with apps, which can provide UI for each view.
  // PatchSmith shows the closest match, falling back to "/" if the app provides it.
  views: {
    "/": z.object({
      user: z.object({ id: z.string(), name: z.string() }),
    }),
  },

  // Slots define where apps render and which views they support.
  slots: {
    page: {
      views: ["/"],
      description:
        "Full screen content accessed via the sidebar. Width and height vary by device; use responsive layouts.",
    },
  },
});
```

<Step title="Create the client">

Create `src/lib/patchsmith-client.tsx` to connect your frontend to the PatchSmith API. Map each contract component to its React implementation. The example assumes your `Button` and `Input` components accept the props shown below.

```tsx src/lib/patchsmith-client.tsx
"use client";

import { Button } from "@/components/button";
import { Input } from "@/components/input";
import { contract } from "@/lib/patchsmith";
import { createClient, primitives } from "patchsmith/react";

export const patchSmithClient = createClient({
  contract,
  // Replace this with your host origin and handler path.
  baseUrl:
    process.env.NODE_ENV === "development"
      ? "http://localhost:3000/api/patchsmith"
      : "https://your-app.com/api/patchsmith",
  components: {
    ...primitives,

    Button: ({ props, children }) => (
      <Button variant={props.variant} onClick={props.onClick}>
        {children}
      </Button>
    ),

    Input: ({ props }) => (
      <Input
        value={props.value}
        onChange={(event) => props.onValueChange({ value: event.target.value })}
      />
    ),
  },
});

export const {
  Provider: PatchSmithProvider,
  RenderSlot,
  useApps,
  useViewContext,
  useViews,
} = patchSmithClient;

export default patchSmithClient;
```

<Step title="Add the API handler">

Mount the handler at your PatchSmith base path. If you use a path other than `/api/patchsmith`, update `baseUrl` in both `patchsmith-server.ts` and `patchsmith-client.tsx` to match.

Choose your framework below. Replace `auth` with your authentication implementation and return verified scope values from the session.

```ts app/api/patchsmith/[...patchsmith]/route.ts
async function handleRequest(request: Request) {
  return patchSmith.handler(request, {
    authenticate: async () => {
      // Replace this with your own authentication logic.

      if (!session) {
        return null;

      return {
```

<Step title="Render a view">

Use `useViewContext` to share page data with apps and `useViews` to find apps available in the `page` slot. Render the selected app with `RenderSlot`.

<Tabs>

<Tab title="Next.js App Router">

```tsx app/app-views/page.tsx
"use client";

import { useState } from "react";
import { RenderSlot, useViews, useViewContext } from "@/lib/patchsmith-client";

export default function Page() {
  const [selectedId, setSelectedId] = useState("");
  const { data: views, isPending, error } = useViews({ slot: "page" });
  // Replace this with your own authentication hook.
  const { data: session, isPending: isSessionPending } = useSession();

  useViewContext(
    "/",
    session
      ? { context: { user: session.user } }
      : { context: undefined, loading: true }
  );

  const selectedView =
    views?.find((view) => view.app.id === selectedId) ?? views?.[0];

  if (isPending || isSessionPending) return <p>Loading views…</p>;
  if (error) return "An error has occurred: " + error.message;
  if (!selectedView) return <p>No views available yet.</p>;

  return (
    <>
      <label>
        View
        <select
          value={selectedView.app.id}
          onChange={(event) => setSelectedId(event.target.value)}
        >
          {views?.map((view) => (
            <option key={view.app.id} value={view.app.id}>
              {view.app.name ?? view.app.id}
            </option>
          ))}
        </select>
      </label>

      <RenderSlot
        key={selectedView.app.id}
        app={selectedView.app}
        slot="page"
      />
    </>
  );
}
```

<Step title="Verify the integration">

Start your host app, then check these endpoints at your configured host origin:

```txt
GET /api/patchsmith/schema
GET /api/patchsmith/meta
GET /api/patchsmith/apps
```

The schema and metadata endpoints describe your public app contract. The apps endpoint requires a valid host session and returns the apps installed for the authenticated scopes. Each scope is named by the schema key, such as `user`.

While signed in to your host, open `/app-views`. You should see either an app view or “No views available yet.” An unauthenticated request to `/api/patchsmith/apps` should be rejected.

If the routes return 404, check the catch-all route and handler path. If the schema works but apps fail to load, check that `authenticate` returns a valid session and that the client points to the same origin as your host.

</Step>
